# Прогресс работ

## Fix 1.0.5+ — почему не работало переключение (разбор по краш-репортам)

Диагноз по `~/Library/Logs/DiagnosticReports` и `debug.log`:

1. **Краш SIGTRAP из колбэка тапа.** `TISCreateInputSourceList`/
   `TISSelectInputSource` вызывались из потока тапа (shift-tap путь);
   HIToolbox требует main-очередь (`dispatch_assert_queue`) — процесс
   погибал. Оба краш-репорта (23.10 00:15 и 20:43) — один и тот же стек.
   Фикс: новый модуль `platform/macos/main_thread.rs` — диспетчеризация
   в главный поток с тайм-аутом; TIS больше нигде не зовётся из тапа.
2. **Жёстко зашит `com.apple.keylayout.US`**, а в системе включена
   пара «ABC» + «Russian» — переключение на EN всегда падало
   («источник не найден»). Фикс: кэш включённых раскладок пары
   (`input_source::refresh_enabled_pair`, en=ABC ru=Russian) и
   `resolve_layout_id` для логических id движка; то же в меню и
   shift-tap. В core `LayoutChanged` теперь считает всё нерусское
   английской стороной пары (раньше распознавался только US).
3. **Гонка «замена раньше смены раскладки»**: `run_on_main_thread`
   асинхронный, а замена печатается keycode-ами сразу — клавиши
   уходили ещё в старой раскладке (текст «не менялся»). Фикс:
   синхронное (с тайм-аутом) переключение до печати замены.
4. **Наблюдатель смены раскладки не работал никогда**: имя
   Darwin-уведомления было поддельным («AppleSelectedInputChanged»).
   Фикс: вшитый CFString `kTISNotifySelectedKeyboardInputSourceChanged`
   из HIToolbox. Теперь флаг в трее и язык движка синхронизируются.
5. **Дедлок-риски**: лок движка больше не держится во время
   `execute()` (внутри — синхронная диспетчеризация в main, который
   сам может ждать лок); NSSpellChecker — через тот же тайм-аут
   вместо голого dispatch_sync (зависимость dispatch2 удалена).

Тесты: +1 в core (ABC в LayoutChanged); 47+18+2 зелёные, clippy/fmt
чистые. После замены бинарника разрешения TCC «залипают» (ad-hoc
подпись, FR-SYS-4): сброшены `tccutil reset` для app.caramba.clone,
пользователю нужно выдать «Универсальный доступ» и «Мониторинг
ввода» заново.

## M6 «Правила» — код готов (локальная проверка)

- **Формат пакета** (`core/src/rules/pack.rs`): контейнер
  `rules-YYYY-MM-DD.pack` = magic `CBCRULES` + манифест (version/date/
  min_app_version/format/SHA-256 содержимого), подпись Ed25519 по
  манифесту, JSON-содержимое. Публичный ключ вшит; максимум 64 МБ.
- **Содержимое** (`PackPayload`): словари RU/EN, n-gram модели
  (триграмма → вес-байт, вес = число слов с триграммой),
  ё-пары, курируемые опечатки, стартовый список исключений.
- **Сборщик** (`tools/rules-builder`): genkey/build/--key env
  `RULES_SIGNING_KEY`; собирает из data/, подключает caramba-core;
  пакет 960 КБ собирается и подписывается локально.
- **Движок**: `Engine::apply_rules_pack` заменяет наборы слов,
  n-gram (`NgramModel::load_counts`), ё-пары и добавляет
  курируемую таблицу опечаток (FR-TYPO-1а: точная замена
  приоритетнее перестановок, сохраняет регистр первой буквы).
- **Клиент** (`src-tauri/src/rules_client.rs`): скачивание curl;
  верификация (подпись+SHA+формат), атомарная установка
  (tmp→rename), применение к движку, откат к встроенному пакету;
  журнал last_check. Команды: `rules_info/_check_now/_rollback`.
  Еженедельная автопроверка (7 дней) при запуске, config
  `rules_autoupdate`, вкладка «Правила» с кнопками.
- **CI**: `.github/workflows/rules-weekly.yml` (cron Monday 03:00 +
  ручной запуск; при неизменном пакете релиз пропускается).
- Тесты: 4 юнита пакета (круговая загрузка, повреждённый хвост
  отвергается, чужая подпись, формат даты), юнит таблицы опечаток
  и применения пакета; 46+18+2+2 — зелёные; clippy -D warnings,
